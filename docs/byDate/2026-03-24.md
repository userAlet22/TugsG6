# Bug Fixes - March 24, 2026

## 1. Staff Maintenance Request Form - Blank Page (Render Crash)
**Issue:** 
When navigating to `/staffmaintenancerequestform/:id`, the route was successfully matched to `StaffMaintenanceRequestForm.jsx`, but the screen rendered completely blank white. This was caused by a `ReferenceError` during rendering. A "Schedule Modal" feature was partially pasted into the component's JSX, but all accompanying React state declarations (e.g., `isScheduleModalOpen`, `scheduleTitle`) and submission functions were entirely missing from the component's logic.

**Resolution:**
Injected the missing state variables into `StaffMaintenanceRequestForm.jsx` and created the logic for `formatDisplayTime` and `handleScheduleSubmit` to fix the reference errors. The component now mounts and renders the schedule modal perfectly.

## 2. Schedule Event Creation - Time Format Validation Error
**Issue:** 
When staff clicked "Create Schedule", the backend rejected the request with the following error constraint from Laravel: `The time field must match the format H:i.` 
The issue stemmed from the frontend's `formatTimeTo24Hour()` function, which appended seconds (`HH:MM:ss` or `13:18:00`). Laravel's strict backend validation was enforcing `H:i` (which expects exactly `HH:MM`).

**Resolution:**
Updated the submission payload in `StaffMaintenanceRequestForm.jsx` to process the `scheduleTime` input through a new `formatDisplayTime()` function, ensuring the time string drops the seconds and explicitly matches the `H:i` requirement (e.g., `13:18`) before being dispatched to the `/schedule-events` API endpoint.
