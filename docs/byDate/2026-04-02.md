# Database Environment Switching Guide

This document outlines the steps to temporarily switch from the shared Tailscale database to your own local database, and how to safely revert back.

## 1. Validating Local Database Readiness
Before switching your backend environment, you need to ensure your local MySQL server is running.
Using MySQL Workbench:
1. Open **MySQL Workbench**.
2. Create or select a connection pointing to your local server (Hostname: `127.0.0.1`, Port: `3306`, Username: `root`).
3. Click **Test Connection**. A successful connection confirms your local server is running. (If it fails, you must start MySQL via XAMPP, Laragon, Docker, or Windows Services).
4. Once connected, ensure you have created an empty database that matches your backend's `DB_DATABASE` name (e.g. `manageit`).

## 2. Switching to the Local Database
If the shared database host goes offline, switch your backend manually:

1. Open `docker-gsobackend/.env`.
2. Locate your database variables and swap them out for your local connection details:
   ```env
   DB_HOST=127.0.0.1
   DB_PORT=3306
   DB_DATABASE=manageit
   DB_USERNAME=root
   DB_PASSWORD=   # Leave blank if you have no local password
   ```
3. Open a terminal in the `docker-gsobackend` directory and run migrations to construct the tables in your empty local database:
   ```bash
   php artisan migrate
   ```
4. Restart your backend server so it can load the updated `.env` values:
   ```bash
   php artisan serve --host=0.0.0.0 --port=8000
   ```

## 3. Reverting to the Shared Database
When Group 1's host is back online and accessible over Tailscale, securely reconnect your backend:

1. Open `docker-gsobackend/.env`.
2. Restore your variables using the shared Tailscale connection details:
   ```env
   DB_HOST=100.74.28.17  # Tailscale IP of the shared database host
   DB_PORT=3306
   DB_DATABASE=manageit
   DB_USERNAME=root
   DB_PASSWORD=23-Shai-01186
   ```
3. Restart your backend server:
   ```bash
   php artisan serve --host=0.0.0.0 --port=8000
   ```

### Important Note on Migrations When Reverting
When switching back to the shared database, **it is NOT necessary** to run `php artisan migrate`. 
- Group 1's database is already fully set up and populated. 
- If you run the command on the shared database, Laravel will just return `Nothing to migrate.`
- **Exception:** The only time you *must* run `php artisan migrate` on the shared database is if you personally built a brand new migration file locally and need to push those new table structures up to the shared environment.
