# Development Log: March 20, 2026

## Issues 
* **Frontend Error**: The local React application repeatedly showed `Failed to fetch` on login.
* **Root Cause**: The Laravel backend (`docker-gsobackend/.env`) was attempting to connect to an offline, remote Tailscale database host (`DB_HOST=192.168.68.140`). Laravel timed out waiting for the database, causing a silent 500 error API response which appeared as a generic fetch error on the frontend.
* **Secondary Issue**: After changing `.env` variables, the backend still failed to connect because Laravel had cached the old configuration into memory.

## Actions Taken
1. **Pivoted to Local Database Development**:
   * Decided to completely bypass the offline Tailscale machine and set up a local database on the host machine to unblock development.
   * Modified `docker-gsobackend/.env` to point strictly to the local machine:
     ```env
     DB_HOST=127.0.0.1
     DB_PASSWORD=23-Shai-01186
     ```
   * *Note: The exact configurations for both the Remote Tailscale and the Local server are now documented in `database_config_backup.md` for future reference.*

2. **Created the Local Schema**:
   * Used **MySQL Workbench** connected to `Local instance MySQL80`.
   * Executed the query `CREATE DATABASE manageit;` to initialize an empty container for the tables.

3. **Cleared Laravel Cache and Migrated Tables**:
   * **Crucial Fix**: Due to Laravel caching the old `192.168.68.140` Tailscale configuration behind the scenes, ran the following terminal command in the `docker-gsobackend` directory to wipe the memory cache:
     ```bash
     php artisan config:clear
     ```
   * Restarted the active `php artisan serve` backend terminal.
   * With the cache wiped and reading `127.0.0.1` properly, ran migrations to successfully instantiate the backend:
     ```bash
     php artisan migrate:fresh --seed
     ```

4. **Navigating the Database GUI (MySQL Workbench)**:
   * **Refreshing**: Clicking the tiny refresh arrows next to **SCHEMAS** is required to sync new tables into the visual interface.
   * **Viewing Accounts**: Expanded `manageit` -> `Tables` -> right-clicked `users` -> `Select Rows - Limit 1000`.
   * **Real-time Live Data**: The data grid is just a static snapshot. To see newly created "Pending Approval" accounts from the frontend, you must click the yellow **lightning bolt (⚡)** inside the SQL editor to re-fetch the data from the database.
